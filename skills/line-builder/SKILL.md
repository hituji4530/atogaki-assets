# line-builder — LINE公式アカウントの構築支援フロー

このスキルは、LINE公式アカウントの配信設計を、**ヒアリング → 設計 → 文面と動くデモ** の順で仕上げる手順書です。
使う人（構築者）は、自分のアカウントを作る本人のこともあれば、クライアントのLINEを請け負う人のこともあります。どちらでも、最後に **クライアントがその場で触れるデモ** を渡せるのがこのスキルの価値です。

成果物は4つです。

1. **設計書**：タグ・シナリオ・キーワード・リッチメニュー・月の通数見込み
2. **design.json**：設計を機械が読める形にしたもの
3. **SQL**：Cloudflare 版のツール（line-cloudflare）にそのまま入れられる設計データ
4. **デモHTML**：友だち追加・ボタン・キーワード・時間経過をブラウザで試せるページ

各ステップで一度立ち止まって確認してください。いきなり文面を書き始めると、分岐の軸がずれて全部書き直しになります。

## ステップ0：決まりごとと型を読む（毎回・必須）

このスキルのフォルダにある次の2つを先に読みます。

- `references/line-rules.md` — 通数・無料になる返信・ボタンの制限・配信の作法・個人情報の扱い
- `references/templates.md` — 業種別の型（美容室／スクール／士業／飲食／個人の情報発信）

## ステップ1：ヒアリング

**AskUserQuestion** で、設計を左右する4点を1回で聞きます。

1. **業種**：選択肢は templates.md の A〜E のうち近いもの＋その他
2. **LINEのゴール**：初回予約／個別相談・問い合わせ／商品・講座の購入／来店・リピート
3. **お客さんの分かれ目**：興味のあるメニュー・テーマで分ける／初めてか通っているかで分ける／まず分けずに始める
4. **配信の頻度感**：控えめ（登録後1週間で4通程度）／しっかり（2週間で7通程度）

続けて、文章で次をもらいます（すでに会話や資料にあれば聞き直さない）。

- アカウント名（店名・屋号）と、話し手の口調（です・ます／親しみ／絵文字を使うか）
- 主な商品・メニューと価格帯
- 登録特典（クーポン・資料・動画など）があるか
- 予約・購入・問い合わせ先のURL（未定なら仮のURLで進め、設計書で「要差し替え」と明記）

ユーザーがヒアリングシートや既存のLP・サイトの文章を渡してきたら、そこから読み取れる項目は質問しません。ユーザーがいない実行（スケジュール実行など）では、型どおりの最も無難な前提を置き、その前提を設計書の冒頭に書きます。

## ステップ2：設計案を出す

型を下敷きに、クライアントの言葉に置き換えた設計案を、次の表で示します。

- **タグ一覧**：タグ名／意味／どこで付くか（選択肢・キーワード・手動）
- **シナリオ（ステップ配信）**：いつ（登録直後・1日後…）／誰に（全員・タグ条件）／目的（価値提供・信頼・案内）／内容の要約
- **キーワード応答**：キーワード／返す内容／付けるタグ
- **リッチメニュー案**：4〜6区画のボタン名と行き先
- **月の通数見込み**：想定友だち数 × 時間差で送る通数 ＋ 一斉配信。必要なLINEのプランまで書く

設計のチェックポイント：

- 登録直後の吹き出しは3個以内。お礼・届く内容と頻度・選択肢の順にする
- 売り込みの前に、価値を渡すメッセージを2〜3通置く
- 予約済み・購入済みの人に同じ案内が届かないよう、except_tag を使う
- 付けたタグが、後の分岐か配信の絞り込みで必ず使われる（使わないタグは作らない）

表を見せたあと、**AskUserQuestion** で「この設計で文面に進むか」を1問だけ聞きます（選択肢：このまま進む／分岐を変えたい／ステップを増減したい）。

## ステップ3：文面を書き、デモと設計データを出力する

### 3-1. design.json を書く

合意した設計に沿って、全メッセージの文面を書き、次の形の JSON にします。作業用フォルダ（スクラッチパッドなど）に `<アカウント名の英字>.json` で保存します。

```json
{
  "account": "ひだまり美容室",
  "goal": "初回予約",
  "first_friend": "さくら",
  "tags": [
    { "name": "興味:カット", "meaning": "カットに興味", "set_by": "登録直後の選択肢" }
  ],
  "scenarios": [
    {
      "name": "ウェルカム",
      "trigger": "follow",
      "steps": [
        { "after": "0", "purpose": "お礼", "text": "{name}さん、友だち追加ありがとうございます！" },
        {
          "after": "0", "purpose": "興味を聞く", "text": "気になるメニューはどれですか？",
          "choices": [
            { "label": "カット", "tag": "興味:カット", "reply": "ありがとうございます！カットのお悩みに合わせた情報をお届けしますね。" }
          ]
        },
        { "after": "1d", "only_tag": "興味:カット", "text": "…" },
        { "after": "3d", "except_tag": "済:予約", "text": "…" }
      ]
    }
  ],
  "keywords": [
    { "keyword": "予約", "match": "contains", "reply": "ご予約はこちらから👇\nhttps://example.com/reserve", "tag": "済:予約" }
  ],
  "richmenu": [ { "label": "予約する", "action": "https://example.com/reserve" } ],
  "broadcasts": [ { "when": "毎月1日", "to": "全員", "idea": "今月の空き状況" } ]
}
```

- `after`：`"0"`（直後）、`"30m"`、`"3h"`、`"1d"`、`"1d12h"` の形。登録した時点から数える
- `choices`：押すとタグが付き、`reply` が無料で返る。`start_scenario` で別のシナリオを始めることもできる
- `only_tag` / `except_tag`：そのタグがある人だけ／ある人は除く
- `{name}` は友だちの表示名に置き換わる
- `richmenu` と `broadcasts` は設計書用（ツールには自動設定されない）

### 3-2. スクリプトで検証し、SQLとデモを作る

このスキルのフォルダの `scripts/build_line_demo.py` を実行します（Python 3、標準ライブラリのみ）。

```sh
python3 <スキルのフォルダ>/scripts/build_line_demo.py <design.json> --out-dir <出力先>
```

- デモの土台は GitHub の `line-cloudflare/demo-template.html` を読みに行きます。ネットワークに出られない環境では `--template` に手元のファイルを指定します
- `設計エラー:` が出たら、LINE の制限違反です。指摘どおり design.json を直して再実行します
- `注意:` は設計上の気づきです。直すか、設計書に理由を書きます

### 3-3. 納品

- **デモ**：`<slug>-demo.html` を Artifact として公開します（ファイルの中身はスクリプトが組み立てたものなので、そのまま公開してよい）。公開ページは非公開で始まるので、クライアントに見せるときは構築者がページの共有メニューから共有する、と一言添えます。Artifact が使えない環境では SendUserFile で渡します
- **設計書**：ステップ2の表に、確定した文面全文と「要差し替え」の一覧（仮URL・仮の特典名など）、月の通数見込みを加えて渡します
- **本番への入れ方**を最後に案内します
  - line-cloudflare を使う場合：`npx wrangler d1 execute line-cloudflare --remote --file=<slug>.sql`（初期構築用。既存の配信の進み具合はリセットされる）
  - エルメ・Lステップなど既存ツールを使う場合：設計書を見ながら管理画面で設定する。そのツールの MCP 接続が使える環境なら、設計書をもとに下書き作成まで代行してよい（配信の実行は必ず人が確認してから）

## 自己点検（納品前）

- 直後の吹き出しが3個以内か、売り込みの前に価値提供があるか
- 済:〇〇 のタグで、行動済みの人への重複案内を止めているか
- すべてのタグに付く導線と使い道があるか（スクリプトの `注意:` が残っていないか）
- 仮URL・仮の特典を設計書の「要差し替え」に漏れなく載せたか
- 月の通数見込みと、必要なLINEのプランを書いたか
- デモで「友だち追加 → 選択肢 → キーワード → 時間を進める」を一通り試し、意図どおりに分岐したか
